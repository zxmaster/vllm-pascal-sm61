## Квантизация
- Оптимум для 4GB: **IQ4_XS** (качество ≈ Q4_K_M, размер −10%; тип Q4_XS есть в маппинге плагина).
- Q4_K_S — допустимая альтернатива. UD-варианты: +качество, +размер (для 4GB обычно невыгодно;
  UD-Q3_K_XL 2.27G — компромисс, но 3-бит).
- Ниже Q4 для агентных задач не рекомендуется (просадка tool-calling надёжности).

## Влияние на контекст (наш v0.28: util 0.88, TQ k3v4_nc ≈ 11.9 KiB/токен, пул 30 882 ток/0.35 GiB)
- 4B IQ4_XS: +273 MB → ёмкость ~54k токенов (было ~31k)
- 4B Q4_K_S: +173 MB → ~46k
- 2B IQ4_XS: +1 493 MB → ~160k (память перестаёт быть узким местом; остаётся скорость prefill)
- 2B UD-Q6_K_XL: +843 MB → ~104k
- (наивная оценка «освободили веса → отдали пулу»; фактическая ёмкость проверить тестом)

## Рекомендации
1. **Qwen3.5-4B → IQ4_XS** (один шаг: скачать 2.31G, MODEL_PATH, тесты) — сохраняет агентность,
   +270MB к контексту/запасу, внутри обкатанного стека.
2. **Qwen3.5-2B IQ4_XS как «heavy-context/light-task» профиль** — вдвое слабее в tool calls
   (43.6 vs 50.3), но контекст-бюджет ×5 и скорость выше; тест-драйв на реальных задачах.
3. Вне стека (если нужен максимум tool-calling на грамм): LFM2.5-2.6B / Granite 4.2 3B /
   LFM2-1.2B-Tool — через llama.cpp (bonsai-стек); в наш vLLM без доработок не поедут.

## Стек-факты
- vllm_gguf_plugin: спец-адаптер Gemma3 + default (маппинги qwen3_5/gemma3/cohere) + diffusion.
  Реально обкатана на этом железе только Qwen3.5-family (наши патчи tiled/GDN/conv1d заточены под qwen3_5).
- Unsloth Qwen3.5-4B/2B: полные наборы IQ2..Q8, UD-варианты, mmproj (vision не используем).

# Deep dive — вторая итерация (2026-09-14)

## Что вышло после Qwen3.5 (февраль 2026)
- **Qwen 3.6/3.7/3.8** (июль–август 2026): только большие (27B, 35B-A3B, Max, Flash-Next ~87 GB).
  Маленьких (2B/4B) в новых поколениях НЕТ. Qwen3.5-4B — по-прежнему актуальный small у Qwen.
- Закрытые новые фронтиры: GPT-6 Astra (OpenAI, сен 2026), Claude Fable 5.1 / Mythos 5.1 (Anthropic).
  Локально недоступны; но задают тренд «reasoning-first», который доходит до маленьких.

## Открытые маленькие — свежие конкуренты 4B-класса
- **MiniCPM5-2B** (OpenBMB, 07.09.2026) — главная находка:
  - 2.52B dense, `LlamaForCausalLM`, GQA 16Q/2KV, **131 072 контекст нативно**, Apache-2.0.
  - Бенчи (по данным OpenBMB): средний 53.9 > Qwen3.5-4B 51.1; **BFCL-v4 66.6**; τ²-Bench Telecom 97.1;
    GAIA Text-103 88.7; SWE-bench Verified 46.4; LiveCodeBench v6 69.1.
    Независимо: AA Intelligence Index 15 — «highest of any open weights ≤4B» (OpenBMB заявляет 23 — не сходится, верить 15).
  - GGUF (bartowski): IQ4_XS 1.36G, Q4_K_S 1.43G, Q4_K_M 1.50G, Q5_K_M 1.79G.
  - **vLLM парсер `minicpm5xml` уже есть в нашей сборке**; day-0 поддержка vLLM/SGLang/llama.cpp/Ollama/MLX.
  - Минусы: think-heavy (длинные reasoning traces, «loops» по отзывам), слабая мультиязычная нюансировка, нет vision.
  - Тренировка: RL + OPD (on-policy distillation, 16 экспертов → один 2B). +10.96 reasoning / +6.96 agentic.
- **Ling 3.0 Tiny** (InclusionAI, авг 2026): 7.9B total MoE, 128K; отзыв тестера: «sub-4GB на Q3, 17 tool calls, zero errors».
  Парсер `ling3` есть у нас; НО веса 7.9B в Q3 ≈3.5G → контекст-бюджет мал для 4GB карты.
- Прочие из сравнения OpenBMB: LFM2.5-2.6B (33.2 в их сете; 56.9 BFCL в llm-stats — источники расходятся),
  Granite 4.2 3B (42.7 их / 52.4 BFCL llm-stats), Nemotron-3-Nano-4B, Gemma-4-E2B/E4B.

## Вывод второй итерации
- «27B-качество в 2 ГБ» не существует ни у кого; реалистичный максимум сегодня —
  паритет с 4B-классом + 128K контекст + агентный профиль: это MiniCPM5-2B.
- Для нашего 4GB: MiniCPM5-2B (1.36–1.5G весов) даёт +1.0–1.1G бюджета против 4B-Q4:
  при тех же настройках пул ~34k токенов без TQ и ~90k с TQ (оценка); скорость декода ожидаемо ×2–4.
- План: (1) Qwen3.5-4B → IQ4_XS [внедряется], (2) пилот MiniCPM5-2B отдельным профилем
  (LLM-парсер есть, GGUF есть; риски: загрузка не-qwen через vllm_gguf_plugin, TQ на llama-арке).
